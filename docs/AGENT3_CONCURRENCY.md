# Agent3 并发排查与修复

## 跨窗口内存保护

多个窗口可以同时提交 Agent3，但跨窗口同时仅启动一个 Agent3，其他任务先进先出排队。
只有当前工作线程和识别子进程实际退出后才释放名额；取消等待中的任务不影响其他窗口。
Agent1、Agent2 仍在各窗口独立运行，不等待其他窗口的 Agent3。

这是项目之间的调度限制；单个 Agent3 内部的有界页面、推理和网络流水线继续运行。
排队任务不会启动 Agent3、加载其模型或渲染其高分辨率页面。
此策略限制多个 Agent3 的内存叠加，不保证单个超大项目或其他程序不会耗尽内存。
所有参与窗口应使用本次更新后的程序；旧版无限制并行窗口不受新队列管理。

## 已修复的串行退化

| 位置 | 原行为 | 修复 |
| --- | --- | --- |
| `service.py` 页调度 | 页线程阻塞于表格 Future；两个慢表格就能挡住后续页面检测 | 页阶段等待依赖时退出线程，Future 完成后再调度 |
| Qwen 结果收集 | 页线程等待所有 Node OCR，后续页无法持续填充检测和 OCR 队列 | OCR 全部完成后恢复页阶段；保留按 Node 顺序匹配名称 |
| Claude 页复核 | 同步 HTTP 请求占用页线程 | 使用独立、有界复核池，完成后恢复几何构建 |
| Tracker / Box | 同页两种模型依次调用 | 同时提交，路由器继续限制实际推理并发和 CPU 线程预算 |

`pipeline.py` 负责恢复页阶段；网络完成回调只提交工作，不执行几何处理。
页面结果仍按页号排序，单个模型、表格或 OCR 失败仍走原有问题记录与回退。

## 资源与依赖

- `AGENT3_PAGE_WORKERS` 仍限制本地页处理以及完整 RGB 位图数量，默认 2。
- Node 裁剪在有界本地池中并行压缩，等待网络前关闭完整位图；等待中的页仅保留压缩裁剪及结构数据。
- `AGENT3_IO_WORKERS` 继续控制 Qwen 并发；表格和复核使用独立池。
- YOLO 配置按每个活动页两种独立模型计算，仍受 `AGENT3_YOLO_WORKERS` 和 CPU 预算约束。
- 表格 → Qwen、Qwen → Claude 是提示词所需的真实数据依赖，保留。
- 渲染仍流式供页；PDF 渲染没有新增跨线程并发。
- 取消时停止恢复待处理页面，并等待已启动的推理和网络调用退出，避免重试与旧请求重叠。

## 回归验证

`tests/test_ai_statistics_agent3_speed.py` 使用 Event/Barrier 验证：

- 单个页线程在表格、OCR、复核任一阶段被阻塞时，仍能启动第三页检测。
- 第一页在上游仍未完成供页时就能进入网络阶段。
- 同页模型调用、Node 裁剪压缩和 OCR 请求实际重叠。
- 网络等待前完整位图已关闭，完整页并发上限仍有效。
- 页面顺序、进度计数及取消后等待已启动请求的行为保持有效。

这些测试验证调度和回退语义，不代表真实 YOLO、Qwen、Claude 服务的端到端加速比。
