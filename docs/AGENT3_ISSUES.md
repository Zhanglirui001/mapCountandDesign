# Agent3 问题管理

## 维护入口

- `application/ai_statistics/element_recognition/issues.py`：22 种问题的枚举、级别、消息模板与生命周期。
- `service.py`：业务触发条件，以及检测、OCR、几何计算等阶段的降级处理。
- `issue_review.py`：人工编辑后重新检查受影响的问题，并同步树、标注和检测框的问题引用。
- `contracts.py`：问题数据结构、稳定标识和 `ElementRecognitionResult.all_issues`。
- `workflow.py`：运行异常和取消的边界，以及人工编辑结果的保存入口。

新增规则时，先在 `IssueCode` 和 `ISSUE_DEFINITIONS` 注册，再在拥有相关输入的业务分支调用 `create_issue(...)`。调用处传递页码、实体、框位置和模板参数，不自行选择严重级别。不需要新增规则引擎，也不要把所有业务判断搬到目录文件中。

调整已有问题的级别，修改目录；展示措辞按下文维护翻译表。IoU 和长度偏差阈值继续由业务侧的具名常量管理；IoU 提示使用实际阈值作为模板参数。

## 国际化

`create_issue` 保存英文诊断消息及结构化 `params`，不读取 UI 语言。UI 使用 `format_issue_message(issue, tr)` 在显示时翻译，所以已有结果可以直接切换语言，后台子进程也不依赖 GUI 翻译状态。

三种语言的文案位于 `i18n/translations/{en_US,zh_CN,pl_PL}.json`，键名为 `ai_statistics.element_recognition.issue.<code>`。修改展示文案时更新翻译表；目录中的英文模板作为诊断消息和缺少翻译时的回退。新增规则需要同时补充三种语言，模板参数名及数字格式应保持一致。

问题搜索支持当前语言提示、原始英文消息和问题代码。代码、定位标识和忽略状态不受语言影响。第三方服务返回的错误详情保持原文，前面附上翻译后的操作失败说明。旧结果缺少参数、未知代码或模板格式错误时回退到原始消息。

JSON 导出新增 `params` 字段，保留英文 `message` 供诊断；参数可随 Agent3 子进程结果一起传输。

## 问题与运行失败

Warning 表示需要关注的不确定结果；Error 表示局部失败或结果问题。二者都可以与可复核结果一起返回，不因级别自动中止或禁止确认。

输入非法、无法生成任何 Node、子进程退出等不能继续执行的情况，仍走异常路径，由工作流标记 `FAILED`。用户取消单独处理。此次修改没有改变识别时的触发条件、级别或工作流阻断策略。

`EXECUTION` 问题记录检测/OCR/复核调用失败，人工修正结构不会删除这些执行记录。`RESULT` 问题随其输入的编辑而更新；与本次编辑无关的检测证据继续保留。

## 存储和读取

页面问题仅存于 `page.issues`；跨页问题存于 `result.issues`。读取完整列表、统计总数或提供 UI 数据，统一使用 `result.all_issues`。它也能读取旧结果中重复存于根和页面的问题，并优先采用页面版本。

JSON 导出仍按页面/项目分别保存问题，根级 `issues` 不再重复包含页面问题。消费导出的程序应读取这两个作用域。

问题标识为 `(code, page_number, entity_id)`，不含文案、严重级别或坐标；改提示文案不会重置 UI 的忽略状态。同一页、同一对象、同一代码应聚合为一条问题。新增不同对象的问题必须提供不同的实体标识。

`RecognitionIssue` 仍是可直接构造的数据契约，以兼容已有调用者；生产规则使用 `create_issue`，避免依赖数据契约的默认 Warning。

## 人工编辑后的处理

- 修改已有识别 Node 的名称或组串表：重新检查页面内重名和表格匹配；名称被修正后清除占位名提示。
- 修改已有识别 Node 的排结构或 OCR 参考数量：重新检查当前排结构的 Tracker/组串数量，不覆盖 OCR 来源值。
- 修改 INV 名称：清理已解决的名称歧义，并重新匹配 Agent2 名单。
- 修改 Box 位置：清除对应的单排位置歧义。不会将缺少 Box 检测或重叠检测框当作已经修复。
- 应用组串表并重建几何：保存新产生的问题，替换旧几何问题，并重新检查 Tracker 长度偏差。
- 删除识别 Node：移除它及下属检测对象的结果问题，保留执行失败记录。

没有识别标识/页面来源的纯手工 Node 不参与页面检测问题的刷新，其业务数量仍由 Agent4 校验。检测框重叠、未归属对象等问题在仅编辑结构时保留，因为原始检测数据没有被修改。以后若增加检测框编辑功能，应在该编辑入口重算这些规则。

## 验证

`tests/test_agent3_issues.py` 覆盖目录约束、稳定标识、旧结果去重、人工编辑修复和执行记录保留。几何与 UI 测试覆盖表格错误的新增/消除、检测框引用同步和忽略状态。保留原有识别、降级、工作流、导出和取消测试以防行为回归。
